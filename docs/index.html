Meeting notes in. Shipped tickets out.

Three AI agents read your meeting notes, open GitHub issues through the Model Context Protocol, and draft follow-up emails to each owner — wired up as a Django app you can run locally in minutes.

View on GitHub → Quickstart

01What it does

Paste the notes from your weekly sync. The crew does the next 20 minutes of busywork for you.

// extract

Parses action items

Finds every commitment and matches owners strictly against your roster — no hallucinated people.

// open

Opens GitHub issues

One issue per task in the repo you choose, assigned to the right person, through the official GitHub MCP server.

// draft

Drafts follow-up emails

One short email per owner listing only their tasks with issue links, plus a 3-line team summary.

02How it works

A sequential CrewAI pipeline. Each agent passes structured Pydantic output to the next. The middle agent gets exactly one tool.

tools: issue_write
Agent 03

Comms Writer

Writes one email per owner with issue links, plus a 3-line meeting recap for a team channel.

tools: none

03Stack

Deliberately small and inspectable — every piece is swappable later.

web
Django 6.1 — admin, ORM, templating. One-stop frontend/backend.
agents
CrewAI — sequential multi-agent pipeline with Pydantic-structured outputs.
tool bridge
crewai_tools.MCPServerAdapter — wraps MCP tools as CrewAI BaseTools.
external tools
GitHub MCP server — the official Go binary; stdio transport.
llm
OpenAI gpt-4o-mini — fast, cheap, good at structured outputs.
data
SQLite — zero infra for the quickstart.

04Quickstart

Clone, install, point at a sandbox repo, run. The whole loop in < 10 minutes once you have Python 3.13 and Go. 

git clone https://github.com/ArunaSivaram/meetingcrew
cd meetingcrew
python3.13 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Build the GitHub MCP server binary
git clone https://github.com/github/github-mcp-server
(cd github-mcp-server && go build -o github-mcp-server ./cmd/github-mcp-server)

# Configure .env with GITHUB_PERSONAL_ACCESS_TOKEN, GITHUB_MCP_BINARY,
# OPENAI_API_KEY, OPENAI_MODEL_NAME

python manage.py migrate
python manage.py createsuperuser    # for /admin
python manage.py runserver

# Try the crew end-to-end
python scripts/test_crew.py

05Honest caveats

This was built to learn, not to ship. A few things to know before pointing it at a real repo.

PAT permissions: Fine-grained PATs may create issues but silently drop assignees. Give the token explicit Issues: Read & write, or use a classic PAT with repo.
Agent hallucinations: If a tool keeps failing, the LLM may fabricate a successful response. Verify side-effects (actual issues on GitHub) against the external system — never trust the agent's own claim.
Cost & blast radius: Running the crew calls OpenAI and creates real GitHub issues. Point it at a sandbox repo.
